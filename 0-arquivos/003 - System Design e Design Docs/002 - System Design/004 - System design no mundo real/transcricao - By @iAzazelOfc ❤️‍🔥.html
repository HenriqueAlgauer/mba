Bom, pessoal, passado essa parte, esse parênteses para falar sobre System Design nas Big Techs, a gente vai falar também sobre System Design no mundo real. O System Design não é um processo para você passar em processo seletivo. Com certeza as Big Techs utilizam isso para conseguir te avaliar, mas o System Design no dia a dia é algo que não pode faltar se você está desenhando uma solução. Você vai perceber que a maioria dos arquitetos de solução que trabalham no Google, Microsoft, esses caras têm técnicas, têm passos, e obviamente que cada corporação tem uma forma de fazer, mas no mundo real isso é extremamente importante, porque senão você não consegue nem propor nada para o seu cliente.

Então, o System Design vai te ajudar a seguir um raciocínio lógico para que você consiga aproveitar, apresentar algo que faça sentido para todo mundo que for ver.  O que acontece? O System Design é uma ferramenta na mão do arquiteto de soluções. Ele é a forma do arquiteto se expressar. E uma coisa que é importante é o seguinte: um sistema eventualmente tem tanta complexidade, mas tanta complexidade, que se você tentar falar tudo de uma vez, de alguma forma, vai ficar muito complexo. Então, se você tem uma maneira organizada, estruturada, de se expressar para que as pessoas consigam entender a forma como você está desenhando a solução… o System Design vai te ajudar nisso.

Uma coisa interessante também é que o System Design vai fazer com que você tenha mais convicção daquilo que você está entregando. Uma coisa é eu estar em uma reunião e alguém fazer alguma pergunta e eu começar a dar determinadas soluções. Quando eu estou fazendo isso, eu não estou “sentando”, eu não estou me concentrando, eu não estou digitando. Perceba, cada vez que você formaliza alguma coisa, você vai perceber que tem mais tempo de refletir em cima daquilo. Um exemplo muito claro é quando você trabalha com TDD (Test Driven Development). A gente começa a fazer os testes, concordam comigo? E toda vez que você vai criar o teste antes do software, significa que você está pensando muito mais naquele problema do que necessariamente  se você já fosse sair codificando. Então, no final do dia, o System Design vai gerar convicções muito mais fortes porque você está tendo tempo de pensar realmente na solução.

E, obviamente, System Design ajuda a vender. A forma como você vai vender para o seu cliente, vai ser totalmente dependente de como você vai conseguir fazer esse System Design para você conseguir fazer a sua apresentação. Você vai perceber que, se você for trabalhar nessa área de arquitetura de solução, você vai fazer reuniões junto com a área comercial; vai fazer reunião com a área técnicas e etc. E você vai perceber que a única arma que você tem naquele momento para conseguir apresentar aquilo que você precisa é o seu System Design. E você vai perceber que o System Design não é apenas desenho. O System Design é um conjunto de artefatos. Então, isso é um ponto importante. E é aquilo que eu já falei um pouco, especificar e documentar. Todo momento que você especifica e documenta algo, isso vai fazer com que os clientes não possam falar que você está funcionando no “chutômetro”. Você vai estar justificando as suas próprias decisões e você vai perceber que, quando você não formaliza aquilo que você está fazendo e você fala alguns números, dá alguma decisão: “ah, vamos utilizar, então, o Apache Kafka”. Justifique para mim, por que utilizar o Apache Kafka é melhor? Então, isso é um ponto importante. Logo, fazer System Design é também conseguir pensar nos trade-offs, e justificar a maneira como você está pensando para as outras pessoas.

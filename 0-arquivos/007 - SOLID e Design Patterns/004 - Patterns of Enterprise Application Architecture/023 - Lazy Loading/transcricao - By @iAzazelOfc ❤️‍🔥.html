Bom, pessoal, eu acredito que muita gente já ouviu falar em Lazy Load. A gente tem até um exemplo de como as coisas funcionam. Qual é a ideia do Lazy Load? É de você conseguir pegar registros. Mas, às vezes, existem dados nesses registros que você não sabe se você vai precisar deles ainda ou não. Então, para que você não gere um consumo muito grande de memória, o que você faz? Você faz a solicitação dos dados e esses dados ainda não batem no banco de dados. A gente cria uma espécie de um proxy. Esse proxy simplesmente marca. Se alguém chamar esses dados realmente, o proxy vai, bate no banco de dados e traz os dados. A gente tem um objeto fake para gente, dizendo temos todos os dados que a gente pensa que a gente tem, entendeu? Então, o Lazy Load ajuda para caramba evitar que você fique batendo no banco de dados o tempo inteiro. Ele consegue sim trazer os dados somente quando você precisar ,e ainda assim, você consegue trabalhar com os seus objetos normalmente. Por quê? Porque ele bota nos objetos que ele não carregou os dados, um fake. E quando você chamar o fake, ele chama o proxy e traz os dados para você.

Então, o Lazy Load é o seguinte, um objeto que não possui todos os dados que você talvez precise, mas ele sabe onde buscá-lo. Esse é o grande ponto. Eu não tenho os dados ainda, mas se você precisar, eu vou lá rapidinho, busco e trago para você. É basicamente isso, como ele funciona. Então, é o seguinte, o Lazy Load carrega os objetos somente quando necessário. No carregamento inicial, os dados reais são substituídos por proxies ou sena, ou seja, apenas representações do objeto real sem os dados. Assim, você tem um cara, você pensa que ele é sua entidade usuário, você pensa que quando você dá um get pedidos, ele vai trazer os pedidos desse usuário, mas esse seu pedido, que você pensa que é um array, é um proxy. No final das contas, é isso. Quando os dados relacionados são acessados, o proxy carrega os dados do banco. No final das contas, você sempre vai ter esses proxies.

Esses proxies vão fazer o mapeamento fake para você. Então, essa é a ideia do Lazy Load. Uma coisa que muitos ORMs, principalmente no passado, tinham, um problema muito grande, mas  a gente ainda vê esse problema direto, é o problema com o “N+1”. O que acontece? Imagina que eu quero pegar os pedidos do Wesley. Então, ele não faz o carregamento total, porque a gente está fazendo o carregamento lazy. Mas vamos imaginar que na hora que eu precisar do meu pedido, dos pedidos mesmo, o que vai acontecer? Eu tenho que fazer consultas individuais desses pedidos. E o que vai acontecer? Ele vai realizar uma pancada de consulta. Ou seja, ele vai ter aquele problema do “N+1”, ou seja, para cada registro ele faz uma consulta. E imagina se você tem 100 pedidos, ele vai realizar 100 consultas para você. Quando você não utiliza carregamento lazy, normalmente com apenas uma query SQL você consegue trazer todos os dados de uma vez, sem precisar ficar fazendo um monte de consulta. Então, sempre, mas sempre coloque um log para você ver quais são as queries SQL que o seu RM está fazendo, somente para você garantir que não vai ter problema com o “N+1”. Ter problema com o “N+1” é um problema absolutamente “ridículo” e que vai acabar com a performance da sua aplicação e vai fazer rapidinho com que o seu banco de dados vire um gargalo para você. Maravilha? Então, é isso, lazy loading.

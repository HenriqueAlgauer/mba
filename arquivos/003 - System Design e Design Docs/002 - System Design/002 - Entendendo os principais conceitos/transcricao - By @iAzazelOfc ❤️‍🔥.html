Primeira coisa, a gente vai falar sobre o que é System Design e a sua importância.A gente vai falar sobre os principais fundamentos do System Design, depois disso, a gente vai falar sobre requisitos e análise do problema que a gente vai enfrentar. A gente vai entender como criar planos de capacidade, vai falar sobre modelagem de dados e vamos fazer uma aplicação na prática do System Design em si. Então, pessoal, para ir direto ao ponto, o que é o System Design? O System Design é um processo de definição de arquitetura, componentes, módulos, interfaces e dados para atender os requisitos especificados. Essa é a ideia de como funciona e o que é, no final do dia, o System Design. Então, de uma forma geral, se você pensar bem, ele é um processo para gente definir a arquitetura. Ponto! 

Porém, muitas pessoas pensam que System Design é apenas desenhar a arquitetura e é nesse ponto que normalmente as pessoas estão enganadas. Por quê? Porque o System Design tem uma importância além daquilo que você apenas desenha para alguém entender a sua arquitetura. Ele vai muito além disso. Então, vamos entender desde o início a importância do System Design.

Toda vez que a gente está pensando no System Design, a gente está pensando na arquitetura de forma intencional. O grande problema é que, muitas vezes, a gente vai desenhar uma arquitetura e a gente coloca “a mão”, colocando logo os load balancer, já colocamos aplicação e etc. está pronto. Mas não, o System Design pelo fato de ele ser um processo; ele faz com que você siga algumas etapas e cada uma dessas etapas vai fazer com que você pense de forma intencional no problema que você vai resolver. Então, o que acontece? Ele te ajuda a racionalizar as definições que realmente importam. Logo, tudo que realmente importa é onde a gente vai “pegar”. 

O System Design não vai ser um documento que vai conter todos os detalhes de arquitetura. E muito do que você vai ver são aproximações para que a gente consiga dar uma base para as pessoas interessadas. A gente vai trabalhar muito em aproximação aqui. Ou seja, aproximar é mais importante do que gastar muitas e muitas horas pensando ser muito assertivo. Então, a gente vai pensar nos pontos que nos importam aqui. E o que eu acho mais interessante de tudo isso é que, uma vez que você cai em cada um desses processos, você vai perceber que você começa a explorar diversos tipos de solução para tentar fazer a conta fechar. Isso realmente é fantástico. E uma vez que você consegue pensar um pouco mais nessa solução, você consegue pensar: "poxa, isso aqui, para eu sair hoje com esse software, eu vou ter essas implicações, mas daqui a cinco anos esse software vai ter essas implicações”. Isso pode ser, por exemplo, o gasto que eu vou ter no storage por dia, ou o quanto eu vou ter de storage ocupado daqui a cinco anos. Então, toda vez que você está pensando em System Design, você não está pensando em apenas fazer desenho. Você está pensando em processos de definição de arquitetura. Uma coisa que é interessantíssima é que todas as vezes que você estiver fazendo esse processo do System Design, você vai ver que você vai estar exercitando a sua mente para que você consiga planejar diversos tipos de solução.

Às vezes, com um problema você pode encontrar dez soluções e baseado nessas dez soluções você vai entender qual é a que importa ou o que faz mais sentido para o contexto daquele negócio. Então, eu vou dar um exemplo muito claro. Às vezes, você quer que a sua aplicação seja rápida o suficiente para algumas determinadas ações. E para fazer aquilo você vai precisar de um cache, um cache em memória, mas com esse cache em memória você vai ter “tanto” de resultado. Agora, se você for pensar em questões financeiras, cache em memória é muito caro. E se eu não fosse fazer cache em memória. E se eu fizesse uma outra abordagem, qual seria a diferença de uma coisa para a outra? Entende o que eu estou dizendo? Quando você está nesse processo de exploração, você consegue colocar as contas na ponta do lápis para que você consiga gerar a melhor solução possível para as suas aplicações.
